# Delivery Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Track verification in the delivery progress ledger.

**Goal:** Implement the approved delivery-only checkout and fulfillment flow in both repositories.

**Architecture:** Extend the existing asynchronous DomainStore and paired Drizzle schemas. Keep one fulfillment status and separate payment status; reuse durable Stripe recovery and transactional history/Activity. The frontend uses the same GraphQL contract on both providers.

**Spec:** [backend delivery](../../../specs/delivery/SPEC.md) and [frontend delivery](../../../../frontend/specs/delivery/SPEC.md).

## Global Constraints

- USD, Stripe test mode, no new runtime dependency; no provider network calls inside transactions.
- SUBMITTED → PREPARING → SHIPPED → DELIVERED; CANCELLED only before shipment.
- Explicit configured countries and fee; delivery disabled by default; demo fixtures use 500 cents.
- Required immutable delivery address and reviewed fee/total; saved retries survive configuration changes.
- Preserve migration histories; reject populated pre-delivery orders; no persistent PostgreSQL reset.
- Addresses/phones/tracking URLs stay out of Activity, provider metadata and logs.
- Generate resolver/client types and paired migration metadata from source definitions.

## Review Focus

- An uncertain checkout retry after fee/country changes must retain its original destination, money and key.
- Shipping versus cancellation on independent PostgreSQL connections must produce one valid outcome.
- Late quote responses after input edits must never authorize payment for stale inputs.
- Old browser data must clear once without clearing new carts on ordinary reload.
- Persistence failure during shipment/history/Activity must roll back all delivery writes.

**Ownership:** Backend src/, drizzle/, configuration, backend existing tests except database-parity.test.ts; no frontend edits.

- [ ] Extend paired schemas/adapters/migrations; guards fail before changing populated old orders. Fresh chains enforce matching constraints.
- [ ] Implement authenticated queries, reservation payload comparisons before config/pricing, fee-inclusive provider lines/refunds.
- [ ] Write/run tests for paid prepare/ship/deliver, exact shipment retry, invalid transitions, cancellation/refund and transactional rollback.
