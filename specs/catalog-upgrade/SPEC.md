# Catalog filtering and sorting contract

**Status: Implemented**

## GraphQL contract

The public catalog query is additive and remains unauthenticated:

```graphql
enum CatalogSort { DEFAULT TITLE_ASC PRICE_ASC PRICE_DESC }

books(
  search: String
  genre: String
  inStockOnly: Boolean = false
  minPriceCents: Int
  maxPriceCents: Int
  sort: CatalogSort = DEFAULT
  limit: Int = 12
  offset: Int = 0
): BookPage!
```

`Book` and `BookPage` did not change. Omitted or null additive arguments retain the
legacy search, ID-order, limit, and offset behavior. `genres` remains public and
independent of catalog filters, sorting, and pagination.

## Selection, validation, and ordering

Archived books are always excluded. Text search remains a trimmed, literal-wildcard,
case-insensitive match over title, author, and genre. `genre` is a separately trimmed,
case-sensitive exact stored-value match; an unknown value is a valid empty result.
`inStockOnly` requires `stock > 0`. All supplied predicates combine with AND, and the
database uses the same predicate for both `total` and `items` before pagination.

Price bounds are stored integer cents, inclusive, and independently optional. They
accept 0 through 1,000,000; equal bounds select one price and one omitted bound stays
open. Search and genre accept at most 100 characters; `limit` is 1–24 and `offset` is
a nonnegative integer. Reversed/out-of-range bounds and validation failures return the
existing `BAD_USER_INPUT` convention. GraphQL coercion rejects invalid scalar and enum
types, and the server maps the sort enum to fixed SQL expressions.

`DEFAULT` is ID ascending. `PRICE_ASC` orders price ascending then ID ascending;
`PRICE_DESC` orders price descending then ID ascending.
`TITLE_ASC` uses ASCII-only A–Z folding followed by binary/C ordering and ID; Unicode
is otherwise left untouched. SQLite uses `lower(title) COLLATE BINARY`; PostgreSQL
uses `translate(title, 'ABCDEFGHIJKLMNOPQRSTUVWXYZ', 'abcdefghijklmnopqrstuvwxyz') COLLATE "C"`.
This is intentionally not a promise of universal Unicode lowercase or locale sorting.
An offset beyond the filtered total returns the total and an empty item list.

## Boundaries and operations

The change flows through book schema, resolver, service, validation, repository, and
both provider adapters. It adds no database migration, environment variable,
dependency, admin catalog behavior, authentication, price mutation, payment, or stock
reservation change. Resolver types are generated by backend codegen; frontend documents
are generated against this contract.

Deploy backend before frontend. The additive arguments keep old clients compatible;
roll back the frontend before removing backend support.
